# 交易回测组合参数优化设计规格

## 批准方向

- 批准时间：2026-08-04（恢复首版优化范围）。
- 批准依据：用户要求将规则 A/B 参数化并寻找最佳组合，随后明确回退受限优化范围；沿用已批准的交易回测浅色研究工作台，不引入新导航或品牌样式。
- 页面位置：本地复盘台 > 交易复盘 > 交易回测 > 组合参数优化。
- 页面目标：让交易者定义规则 A 的持仓上限候选值与规则 B 的每日亏损线候选值，运行完整笛卡尔积回测，看到最高总盈亏组合及其相邻候选证据。
- 排名目标：`maximize_pnl_v1`，只按总盈亏降序确定主排名；总盈亏相同时依次选择更低持仓上限、更低每日亏损线和稳定参数 hash。

## 默认参数与业务合同

| 参数 | 默认候选 | 校验 |
| --- | --- | --- |
| 规则 A · 持仓上限 | `50, 100, 150, 200, 300, 500, 1000` 股 | 正整数、去重、升序，安全上限 100000 |
| 规则 B · 每日亏损线 | `500, 1000, 1500, 2000, 2500, 3000, 3500, 4000, 4500, 5000` USD | 正数、去重、升序，安全上限 1000000 |
| 组合数 | 默认 70，最多 120 | 完整笛卡尔积；不允许只计算 Top N |
| 优化目标 | 总盈亏最大 | 首版固定，不提供多目标权重 |

## 页面结构

1. 保留现有四个复盘子 Tab、共享日期筛选、四场景回测结果。
2. 在四场景结果下新增“组合参数优化”卡片。
3. 顶部左右两列参数输入：每个参数使用逗号分隔候选值，旁边显示单位和校验说明。
4. 固定显示优化目标、最大候选数和“运行组合优化”主操作；进入页面只 GET 最近结果，不自动运行。
5. 完成后先显示最佳组合摘要：规则 A 值、规则 B 值、总盈亏、较基准变化和排名证据。
6. 显示完整候选矩阵；每个单元格由 API 返回 rank/tone，不在浏览器计算 PnL 或最佳值。
7. 显示 Top 10 排名表；标题同时显示“完整 N 组已保存”，明确 Top 10 只是展示投影。

## 组件与状态合同

| 区域 | 文案/行为 |
| --- | --- |
| 标题 | `组合参数优化` |
| 说明 | `组合规则 A 的持仓上限与规则 B 的每日亏损线，按总盈亏寻找最佳值。` |
| 输入 | `规则 A 候选值（股）`、`规则 B 候选值`；支持半角或全角逗号 |
| 主操作 | `运行组合优化`；运行中为 `优化运行中…` 并 disabled |
| 空态 | `当前范围尚无组合优化结果` |
| 最佳结果 | `最佳组合`，显示 A/B 参数、总盈亏和较基准 |
| 候选矩阵 | 行为每日亏损线，列为持仓上限；best/strong/neutral/weak 状态由 API 提供 |
| 排名表 | 仅展示前 10，完整候选仍保存于 artifact 并由 `total_candidates` 证明 |
| 失败态 | 参数错误在提交前可见；来源证据失败时显示后端原因，不生成伪最佳值 |
| 边界说明 | `结果仅用于规则研究，不会自动修改交易配置。` |

## 响应式与可访问性

- 桌面基线：1280×720；参数区两列，最佳摘要单行，矩阵允许容器内部横向滚动。
- 移动基线：390×844；参数区单列，最佳摘要两列指标，Top 10 转为候选卡；页面本身不得横向溢出。
- 输入使用真实 `label`，错误信息通过 `aria-live`；运行按钮具备 disabled 状态。
- 矩阵单元格必须带包含 A/B 参数、PnL、排名的 `aria-label`，不能只靠颜色表达。
- 金额保留两位，股数最多六位小数，状态和排名使用中文。

## 实现 handoff

- Canonical page key：`review/trade-backtest`；无新增顶层 route。
- Canonical component：`TradeBacktestOptimizationWorkbench`，只消费优化 API read model。
- 后端保存完整候选；`Top 10` 和矩阵都是同一完整候选 ledger 的展示投影，不是事实源。
- 允许 live 替换：日期范围、参数候选、组合数、版本、状态、生成时间、候选指标和失败原因。
- 不允许前端计算：PnL、delta、胜率、盈亏比、最佳候选、rank、tone 或候选完成状态。
- 不提供“应用最佳参数”按钮；不修改策略配置、订单、成交或既有回测 run。
- GitHub Pages 静态快照继续保持三个复盘模块，不加入本地优化功能。
