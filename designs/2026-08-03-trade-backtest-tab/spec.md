# 交易回测子 Tab 设计规格

## 批准方向

- 批准时间：2026-08-03。
- 批准来源：用户确认的“交易回测”实施计划。
- 页面位置：本地复盘台 > 交易复盘 > 交易回测。
- 目标用户：需要用历史 committed fills 验证交易纪律的日内交易者。
- 视觉方向：延续当前交易复盘的浅色卡片、蓝色主按钮和紧凑指标表，不引入新的品牌色或导航层级。

## 页面结构

1. 四个复盘子 Tab，桌面单行，窄屏为 2×2。
2. 时间范围筛选，复用全部、本月、本周和特定时间段。
3. 规则说明卡，明确 A、B、C 的执行顺序和阈值。
4. 运行状态栏，展示范围、规则库版本、生成时间及主操作“运行四组回测”。
5. 桌面四行对比表，移动端同一数据投影为四张场景卡。
6. loading、empty、error、partial failure 均为可见状态，不使用空白或零值伪装成功。

## 组件与文案合同

| 区域 | 必须文案或行为 |
| --- | --- |
| 第四 Tab | `交易回测` |
| 主标题 | `历史交易规则回测` |
| 主按钮 | `运行四组回测`；运行中为 `回测运行中…` 并 disabled |
| 空态 | `当前范围尚无回测结果` |
| 部分失败 | `部分规则缺少可用分钟线证据`，失败行显示具体原因 |
| 场景 | `基准`、`规则 A · 200 股上限`、`规则 B · 每日亏损控制（1000 USD）`、`规则 C · 组合规则` |
| 不完整时段 | 覆盖缺口不补造价格，局部质量异常 target 不应用 bars；结果显示 `忽略不完整时段` 的日期/标的数量 |
| 数值 | 金额两位小数，百分比两位，股数最多六位小数；不可用显示 `N/A` |

## 响应式与可访问性

- 桌面基线：1280×720，结果使用语义化 table。
- 移动基线：390×844，结果使用卡片，不出现页面级横向滚动。
- Tab 使用 `aria-pressed`，状态区域使用 `aria-live`，按钮具备明确 disabled 状态。
- 盈利使用现有正向色，亏损使用现有风险色；状态不能只依赖颜色表达。

## 实现约束

- React 只渲染 API 指标，不计算 PnL、胜率、阈值或场景差值。
- `GET /api/review/trade-backtests` 只读取已保存 run；切换 Tab 不自动启动回测。
- GitHub Pages 静态复盘快照继续只有三个子模块。
- 允许的 live 替换仅包括真实日期范围、版本、状态、生成时间和后端汇总数值。

## 偏离与待定

- 无未决设计问题。
- 若实际结果列在 1280px 下无法保持可读，允许表格容器内部横向滚动，但页面本身不得横向溢出；移动端仍必须使用卡片。
